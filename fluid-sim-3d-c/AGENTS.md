# AGENTS.md

이 파일은 `fluid-sim-3d-c`와 그 하위 파일에만 적용되는 프로젝트 전용 규칙이다. 저장소 루트의 [AGENTS.md](../AGENTS.md) 공통 규칙도 함께 적용한다.

## 모드 관리 규칙

- 새로운 물리 현상은 기존 모드를 지우거나 덮어쓰기보다 독립 실행 모드로 추가하는 것을 기본으로 한다. 기존 모드의 삭제·대체는 사용자가 명시적으로 요청한 경우에만 한다.
- 실행 모드를 추가하거나 물리 모델, 렌더링 방식, 성능 특성을 크게 변경하면 `docs/MODES.md`를 함께 갱신한다.
- 모드 전환 키나 관계가 바뀌면 오른쪽 위 HUD, `README.md`와 `docs/MODES.md`의 전환 표를 함께 갱신한다.
- 새 모드는 초기화·해제, 독립 상태 또는 상태 공유 방식, `R` 초기화, 다른 모드와의 왕복 전환, 실제 화면과 성능 검증까지 완료한 뒤 구현 완료로 기록한다.
- 비활성 모드의 상태 보존 여부, 지연 초기화 여부와 초기화 실패 동작을 코드와 문서에 명시한다.

## 아키텍처·연구 문서 규칙

- 모듈 경계, 상태 소유권, compute·render pass, GPU 자원이나 빌드 데이터 흐름이 바뀌면 `docs/ARCHITECTURE.md`를 함께 갱신한다.
- 장기 기술 목표, 참고 논문과 구현 순서가 바뀌면 `docs/CINEMATIC_TARGET.md`를 함께 갱신한다.
- 사용자 조작과 실행 방법은 `README.md`, 모드별 기능·규모·난이도·한계는 `docs/MODES.md`, 내부 데이터 흐름은 `docs/ARCHITECTURE.md`에서 관리한다.
- 논문이나 참고 영상의 결과와 현재 실시간 근사 구현을 구분하고, 구현하지 않은 논문 기법을 현재 기능처럼 기록하지 않는다.

## 검증 규칙

- C 코드 변경 후 경고를 활성화한 전체 빌드를 수행한다.
- GLSL 변경은 shader compile·link 성공뿐 아니라 해당 모드의 실제 화면을 확인한다.
- compute shader 변경은 필요한 memory barrier와 C 구조체/GLSL `std430` 정렬을 함께 검토한다.
- 카메라, HUD와 고정 형식 UI는 지원하는 창 크기에서 잘림·겹침이 없는지 확인한다.
- 성능을 기록할 때 모드, 입자·격자 규모, 해상도, GPU와 VSync 조건을 함께 남긴다.
